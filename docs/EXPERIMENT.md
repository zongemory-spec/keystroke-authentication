# 实验方法与结果边界

## 1. 当前原型实际计算什么

固定文本为 `hello world`，11 次按下和 11 次松开。对第 i 个键记按下时刻为 D_i、松开为 U_i：

| 特征 | 定义 | 数量 |
| --- | --- | ---: |
| Hold | U_i - D_i | 11 |
| Down–Down | D_(i+1) - D_i | 10 |
| Up–Down | D_(i+1) - U_i | 10 |

共 31 维，但不等于 31 个独立自由度：DD_i - UD_i = Hold_i，因此协方差可能奇异。实现使用 Moore–Penrose 伪逆 `np.linalg.pinv`，不是假定增加样本就能消除这些线性关系。

不同键可交叠：前一个键尚未松开时按下后一个键，UD 可以为负，不能将其直接当异常删除。重复字符必须按各自按下事件正确配对。

标准化只拟合训练样本，随后计算模板均值和协方差伪逆。阈值为训练样本到模板的距离均值 + 1.7 × 标准差；新样本距离严格小于阈值才通过。这是当前实现的启发式阈值，不能单凭训练内距离宣布泛化效果。

## 2. 离线合成流程验证

```sh
python demo_evidence.py --out reports/my-evidence.json
```

使用固定 seed 生成 80 个训练样本、20 个同分布留出样本、20 个明显改变节奏的留出样本。三组 seed 不交叠，认证不追加训练数据。脚本通过真实 Flask 路由完成采集、建模和认证，所有 CSV 与模板位于临时目录，不写入项目日常 data/ 或 models/。

记录接受数量是为了观察管线，不将其硬编码成通过条件。改变随机分布不是收集真实冒用者；不能把这两组合成接受/拒绝数量称为真实 FAR、FRR、EER 或认证准确率。安全输入场景另按预期校验，不混为身份识别效果。

首次运行依赖版本与当前代码会影响浮点结果，复现时同时记录环境。输出路径须为新文件，不覆盖旧证据。

## 3. 后续真人评测怎么做

这一部分是尚未执行的实验方案，不是现有结果。

1. 仅招募知情同意的参与者，在本机收集必要时序；不将原始时序或身份模板提交 GitHub。
2. 分开 enrollment、阈值开发与最终测试。按会话/日期切分，禁止将同一条输入放进训练与测试。
3. 训练本人模板；在开发集选择阈值策略并冻结，最终测试不反复调参。
4. 测试本人后续输入和其他参与者对同一身份的声明；记录设备、浏览器、采集会话、样本数与缺失情况。
5. FAR = 被接受的冒用尝试 / 有效冒用尝试；FRR = 被拒绝的本人尝试 / 有效本人尝试。分母为零时结果记为不可计算，不能写成 0%。
6. 分用户与整体报告样本量、失败次数和阈值。小样本结果只对应此次实验；同一个人的重复尝试也不等于独立参与者。
7. 如绘制 ROC/DET 或 EER，使用完整距离分数和明确协议，不能把一次界面的通过/拒绝当作性能曲线。

## 4. 本地界面展示

运行 `python app.py` 后打开 http://127.0.0.1:5000 。自然输入固定文本并释放所有键，采集至少 32 条（建议 50 条以上），建立模板，再用新输入验证。

建议保存三种截图到 `docs/assets/`：采集计数、模板构建反馈、验证时距离与阈值。使用不包含真实身份的代号，并说明截图来自真实手工输入还是合成演示，不混淆二者。

不要用复制粘贴冒充真实按键事件，也不要反复提交同一条样本凑数量。当前接口不防止恶意客户端伪造或重放事件，因此只能用于本地教学原型。

## 5. 数据与模型

本地模板使用 pickle，仅加载自己生成且可控的文件。不要接收下载或用户上传的 pickle。现有输入与路径校验不能将不可信 pickle 变成安全文件。

项目暂未实现活体判断、抗重放、生产登录会话、模板加密或多设备鲁棒认证。不要将本地教学接口公开作为登录服务。
